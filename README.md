# epistemic-ontology.net

Static website + nginx config for **https://www.epistemic-ontology.net/** — a home
for formal, dereferenceable ontologies. It currently hosts the **Record Harm
Ontology** and is laid out to accommodate further vocabularies under their own
slugs.

This site is also the permanent replacement for the placeholder `example.org`
namespace the Record Harm Ontology was drafted under:

```
http://example.org/record-harm-ontology#   →   https://www.epistemic-ontology.net/record-harm#
```

## Layout

```
eon/
├── site/                       # web root (static)
│   ├── index.html              # landing page — lists ontologies, slot for the next
│   ├── style.css
│   └── record-harm/
│       ├── index.html          # human documentation for the namespace IRI
│       ├── record-harm-ontology.ttl   # generated by migrate.sh
│       ├── record-harm-shapes.ttl     # generated by migrate.sh
│       └── example-harm-events.ttl    # generated by migrate.sh
├── nginx/
│   └── epistemic-ontology.net.conf
├── migrate.sh                  # rewrites example.org → epistemic-ontology.net, stages the .ttl
└── README.md
```

## Refresh the hosted ontology

The `.ttl` files under `site/record-harm/` are generated from the source repo,
with the namespace rewritten. Re-run after any ontology change:

```bash
./migrate.sh [path-to-record-harm-ontology]   # defaults to ~/claude/record-harm-ontology
```

It fails if any `example.org` reference survives, so the hosted copy can never
drift back to the placeholder namespace.

> Note: this stages a migrated **copy** for hosting. Adopting
> `https://www.epistemic-ontology.net/record-harm#` as the canonical base in the
> source repository is the ontology's own v3.0 (breaking) release decision.

## Deploy

```bash
# 1. Put the web root where nginx expects it
sudo mkdir -p /var/www/epistemic-ontology
sudo cp -r site /var/www/epistemic-ontology/

# 2. Install the server block
sudo cp nginx/epistemic-ontology.net.conf /etc/nginx/sites-available/epistemic-ontology.net
sudo ln -s /etc/nginx/sites-available/epistemic-ontology.net /etc/nginx/sites-enabled/
sudo nginx -t && sudo systemctl reload nginx

# 3. TLS (Let's Encrypt)
sudo certbot --nginx -d epistemic-ontology.net -d www.epistemic-ontology.net
```

DNS: point `A`/`AAAA` records for `epistemic-ontology.net` and
`www.epistemic-ontology.net` at the server. The apex redirects to `www`.

## Dereferenceable IRIs

`record-harm` uses a **hash namespace**, so every term shares one document.
The bare IRI negotiates by `Accept`:

```bash
curl -H "Accept: text/html"   https://www.epistemic-ontology.net/record-harm   # documentation (303 → /record-harm/)
curl -H "Accept: text/turtle" https://www.epistemic-ontology.net/record-harm   # RDF (303 → the .ttl)
```

A term like `…/record-harm#Destruction` dereferences to the same document
(the fragment is client-side).

## Local preview

```bash
cd site && python3 -m http.server 8000
# http://localhost:8000/   and   http://localhost:8000/record-harm/
```

(Content negotiation on the bare `/record-harm` IRI is an nginx feature; the
plain Python server just serves the static files and the `/record-harm/` page.)

## Adding the next ontology

1. Create `site/<slug>/index.html` (copy `record-harm/` as a template).
2. Stage its serializations under `site/<slug>/`.
3. Add a `map`/`location` pair for `<slug>` in the nginx config if it needs
   content negotiation on a bare IRI.
4. Add a card to `site/index.html` (replace the dashed placeholder).
